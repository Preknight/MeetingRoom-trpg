# 规则数据导出方法（schema `meetingroom-rules/4`）

> 修订记录：
> - 2026-10-29 01:15 初版：记录 V3→V4 的导出思路、字段契约、5etools 的特殊机制与踩过的坑。

本文说明**规则数据包是怎么从 5etools 导出来的、字段什么含义、改了什么之后要重导、导完怎么验**。
它面向的是「以后要改导出或排查数据问题」的人，不面向运行时调用方（那看
`docs/地图视野与特殊区域设计.md` §27 与 `README.md` 的规则查询一节）。

---

## 1 数据源

| 用途 | 路径 | 说明 |
| --- | --- | --- |
| 英文主词条 | `<5etools-en-data>`（例如 5etools 仓库的 `data/`） | 描述文本、数值、机制一律取这一份 |
| 中文关键词 | `<5etools-cn-data>` | 只取 `ENG_name → name` 做 `cnName` 与 `keywords` |
| V3 旧包 | `<previous-rules-data.json>` | 作为增量导出的基底（spells/items/conditions/skills 直接用） |
| 导出脚本 | `tools/export_rules.py`（本仓库） | V4 的导出器 |
| 产物 | `src/MeetingRoom.Host/data/rules/rules-data.json` | 由 csproj 的 Content 规则拷到 exe 同级 `data/rules/` |

**语言策略**：描述文本一律**英文原文**——5etools 的中文翻译有不准的地方，
原文不易歧义。中文只用于 `cnName` + `keywords`（检索用）。

---

## 2 为什么是「增量导出」

V3 包（schema `/3`）里 `spells / items / conditions / skills` 已经完整且正确（做过重印去重），
不需要重导。V3 缺的是：

| 类别 | V3 状态 | V4 处理 |
| --- | --- | --- |
| `monsterTemplates` | 只有 11 个元数据字段，无 hp/ac/特性/攻击 | **补全**（从 bestiary 重新取） |
| `classes` | 不存在 | **新增** |
| `subclasses` | 不存在 | **新增** |
| `feats` | 不存在 | **新增** |
| `optionalFeatures` | 不存在 | **新增**（祈唤/注法/战技/超魔法/战斗风格） |
| `actions` | 48 条，**漏了重印过滤** | **重导**（去重后 31 条） |

所以脚本读 V3 包作基底、只重建上面这些，其余原样搬过去——这样避免重导 spells/items
引入新的差异（那是 V3 已验证过的部分）。

## 3 字段契约（V4）

顶层键：

```
schema            "meetingroom-rules/4"
ruleset           "5e-2024"
strategy          "english-primary-chinese-keywords"
sources           书名集合
monsterTemplates  706
classes           13
subclasses        200
feats             128
optionalFeatures  156
spells            488
items             965
conditions        27
actions           31
skills            18
```

### 3.1 通用字段

每条都带 `id`（`"名称|来源"`）、`name`（英文）、`cnName`（中文）、`keywords`（双语数组，检索用）、
`source`（书名）、`ruleset`（`2014` / `2024`）。

`id` 是稳定主键，工具返回与以后的数据引用都用它。

### 3.2 `monsterTemplates`

```jsonc
{
  "id": "Goblin Warrior|XMM", "name": "Goblin Warrior", "cnName": "地精武者",
  "source": "XMM", "type": "fey", "size": "S", "alignment": ["C","N"], "cr": "1/4",
  "hp": { "average": 10, "formula": "3d6" },
  "ac": [ { "value": 15, "from": [] } ],
  "speed": { "walk": 30 },
  "abilities": { "str": 8, "dex": 15, "con": 10, "int": 10, "wis": 8, "cha": 8 },
  "skills": { "stealth": 6 },          // 字典，值已转 int
  "senses": ["Darkvision 60 ft."], "languages": ["Common","Goblin"], "passive": 9,
  "traits":  [ { "name": "...", "text": "..." } ],
  "actions": [ { "name": "Scimitar", "text": "...",
                 "attackBonus": 4, "damageDice": "1d6 + 2" } ],   // 数值已从文本抽出
  "bonusActions": [], "reactions": [], "legendary": [], "mythic": [], "spellcasting": []
}
```

`attackBonus` / `damageDice` 是**额外抽出来的**：战斗引擎要用，比让模型从文本里抠数字稳。

**用途**：按模板现场放怪、DM 调 HP 与数量来控制强度（CR 只是参考，不参与缩放计算）。

**已知空缺**：706 条里 21 条没有 `hp`——全是召唤物（`Dancing Item`、各种 `* Spirit`、
`Beast of the Land/Sea/Sky`、`Giant Insect`、`Otherworldly Steed` 等），它们的 HP 由**施法者等级**决定，
本来就没有固定值。这不是导出缺陷，调用方要能处理 `hp.average == null`。

### 3.3 `classes` / `subclasses`

```jsonc
// classes
{ "id": "Monk|XPHB", "name": "Monk", "cnName": "武僧", "ruleset": "2024",
  "hitDie": 8, "hitDieCount": 1, "saves": ["STR","DEX"],
  "spellcastingAbility": null, "subclassTitle": "Monk Subclass",
  "skillChoices": [ { "from": ["acrobatics","athletics"], "count": 2 } ],
  "subclasses": ["XPHB|Shadow", "..."],          // 可用子职 id
  "features": [ { "level": 1, "name": "Martial Arts", "cnName": "武术",
                  "text": "...",
                  "references": [ { "type": "refClassFeature", "id": "..." } ] } ] }

// subclasses
{ "id": "Monk - Drunken Master|XGE|XPHB", "name": "Monk - Drunken Master",
  "className": "Monk", "classSource": "XPHB", "classRuleset": "2024",
  "shortName": "Drunken Master", "source": "XGE",
  "featuresInheritedFrom": "PHB",       // ← 只在借用旧版特性时出现
  "features": [ ... ] }
```

`featuresInheritedFrom` 是本 schema 里最重要的一个字段：**2024 版职业下挂着的旧子职通常没有自己的
特性**（如醉拳只有 2014 版内容），导出时回退到旧版并标注来源。200 条子职里有 124 条是这种情况。
没有这个标注，模型会误以为 2024 版的醉拳有新版特性。

`references` 告诉调用方「这条特性还有 N 个可选条目，用 `kind=optional` 去查」。

### 3.4 `feats` / `optionalFeatures`

```jsonc
// feats：category 是关键（FS 战斗风格 / EB 史诗恩惠 / O 起源 / G 通用 / D 龙纹）
{ "id": "Defense|XPHB", "name": "Defense", "cnName": "防御", "source": "XPHB",
  "ruleset": "2024", "category": "FS", "prerequisite": ["..."], "text": "..." }

// optionalFeatures：featureTypes 是数组（5etools 允许一条多类型）
{ "id": "Agonizing Blast|XPHB", "name": "Agonizing Blast", "cnName": "苦痛魔爆",
  "source": "XPHB", "ruleset": "2024", "featureTypes": ["EI"], "text": "..." }
```

`featureType` 速查：

| 值 | 含义 | 归属 |
| --- | --- | --- |
| `EI` | 魔能祈唤 | 魔契师 |
| `AI` | 注法 | 奇械师（**2014 版**；2024 版 EFA 改成了 Replicate Magic Item） |
| `MV:B` | 战技 | 战士·战斗大师 |
| `MM` | 超魔法 | 术士 |
| `FS:F/P/R/B` | 战斗风格 | 战士 / 圣武士 / 游侠 / 吟游诗人（**2014 版**） |
| `PB` | 契约恩赐 | 魔契师（2014 版；2024 版内嵌进职业特性） |
| `ED` | 元素戒律 | 武僧·四象宗 |
| `AS` | 奥术射击 | 战士·奥术射手 |
| `RN` / `RP` | 符文 / 其他 | — |

**注意 2024 版把「战斗风格」变成了专长**（`feats` 里 `category=FS`），
所以查战斗风格要查 `feats`，不是 `optionalFeatures`。同理「史诗恩惠」是 `feats` 的 `category=EB`。

## 4 重印规则（本包的核心策略）

**口径（2026-10-29 确认）：2024 版完全覆盖 2014 版是对的；要保住的是「没有被覆盖的扩展书版本」。**

实现分两套：

### 4.1 按 `reprintedAs` 去重（spells / items / conditions / feats / actions / optionalFeatures）

```python
def drop_reprinted(entries, key_of):
    pool = {key_of(e) for e in entries}
    for entry in entries:
        if any(target in pool for target in reprint_targets(entry)):
            dropped += 1      # 丢弃旧版
        else:
            kept.append(entry) # 目标不在包内 → 保留（这是「未覆盖的扩展书版本」）
```

只有重印目标**确实在包内**时才丢——目标书没导出时不能误删。

效果举例：

| 条目 | 结果 |
| --- | --- |
| `Fireball\|PHB` | 丢弃（`XPHB` 有） |
| `Absorb Elements\|XGE` | **保留**（2024 没重印，扩展书独有） |
| `Bountiful Luck\|XGE`（专长） | **保留** |
| `Disarm\|DMG`（动作） | **保留** |

### 4.2 按「规则版本」收敛（classes / subclasses）

职业不用 `reprintedAs` 判，直接按同名取最高规则版本：

```python
# 同名职业只保留 ruleset == "2024" 的那条
# 子职只保留挂在保留下来的职业版本下的
```

结果：28 条职业 → **13 条，全部 2024**；子职 324 → **200**。

`ruleset` 判定不看名字前缀，看显式集合：

```python
RULESET_2024 = {"XPHB", "XMM", "XDMG", "EFA"}
```

**`EFA`（艾伯伦：工匠熔炉）不是 `X` 开头，但同样是 2024 规则**——早期用 `startswith("X")` 判，
把奇械师误判成 2014，导致「职业来自 TCE、子职来自 EFA」的孤儿关系。

## 5 5etools 的四个特殊机制（都踩过）

### 5.1 `_copy` 继承

原始怪物里 **1144 条**用 `{"_copy": {"name": "基础怪", "source": "MM"}}` 继承属性，
SKT 的命名 NPC 几乎全是。不解析的话 hp/ac/cr 全是 null。

```python
def resolve_copy(monster, index, depth=0):
    base = index.get((copy.get("name"), copy.get("source")))
    merged = dict(resolve_copy(base, index, depth + 1))   # 递归
    merged.update({k: v for k, v in monster.items() if k != "_copy"})
```

本项目数据里 `_mod` 为 **0 条**，所以不需要支持 `_mod` 的数组修改语义。

### 5.2 `reprintedAs` 有三种形态

```python
'Fireball|XPHB'                              # 字符串
'Shadow|Monk|XPHB|XPHB'                      # 子职：短名|职业|职业源|源
{'uid': 'Boots of the Winding Path|EFA', 'tag': 'item'}   # 注法：dict！
```

第三种是注法（TCE→EFA）特有的，不处理会抛异常或静默漏判。

### 5.3 `ref*` 引用节点（最坑的一个）

2024 版职业特性里的可选能力**不内嵌**，而是引用：

```json
{ "type": "options", "entries": [
    { "type": "refOptionalfeature", "optionalfeature": "Agonizing Blast|XPHB" }
]}
```

- 遇到 `ref*` 节点如果不处理，**整段内容蒸发**——「魔能祈唤」特性只剩一句
  “options appear in alphabetical order”，28 条祈唤全没了。
- **坑**：取 ID 的键是 `"optionalfeature"`（小写 o），而类型名是 `"refOptionalfeature"`。
  按 `node_type[3:]` 取到的是 `"Optionalfeature"`（大写 O）→ 键名不匹配 → 取不到。
  必须 `node_type[3:][:1].lower() + node_type[4:]`。

现在的处理：`flat_text` 遇到 `ref*` 输出 `[id]` 占位；`collect_refs()` 额外把引用收进
特性的 `references` 字段。

### 5.4 5etools 的 `{@tag}` 文本标记

`render()` 负责清洗：

```
{@hit 4}          → +4
{@damage 1d6 + 2} → 1d6 + 2
{@atk mw}         → 删除
{@item leather armor|phb} → leather armor
```

另外为了战斗引擎，`named_blocks()` 会从 action/trait 原文里**抽出** `attackBonus` 与 `damageDice`。

## 6 重新导出

```bash
cd <repo>

python tools/export_rules.py ^
  --en   "<5etools-en-data>" ^
  --cn   "<5etools-cn-data>" ^
  --base "<previous-rules-data.json>" ^
  --out  "src/MeetingRoom.Host/data/rules"
```

（在 Git Bash 里把 `^` 换成 `\` 或写成一行。）

产物：`rules-data.json`（约 4.2 MB）+ `export-report.json`。

**什么时候需要重导**：

- 换了 5etools 版本（数据包升级）
- 改了重印口径（比如决定收某本新扩展书）
- 发现某类字段缺失（先查 `export-report.json` 的计数）

**加一本扩展书**：改 `DEFAULT_SOURCES`，如果是 2024 规则同时加进 `RULESET_2024`。
注意 `DEFAULT_SOURCES` 变更会改变「重印目标是否在包内」的判断，可能连带影响去重结果——
改完必须看 `export-report.json` 的各类计数是否合理。

## 7 校验

导完先看 `export-report.json`：

```jsonc
{
  "problems": [],                    // 必须为空
  "monsterTemplates": { "total": 706, "withHp": 685, "withCr": 665,
                        "withTraits": 474, "withActions": 694, "missingRaw": 0 },
  "classes":    { "total": 13, "multiVersion": [], "featureCount": 302 },
  "subclasses": { "total": 200, "inherited": 124, "legacyOnly": 0, "featureCount": 1388 },
  "feats":      { "total": 128, "byRuleset": { "2014": 23, "2024": 105 } },
  "optionalFeatures": { "total": 156, "byType": { "EI": 58, "AI": 16, ... } }
}
```

几个关键判据：

| 判据 | 期望 |
| --- | --- |
| `problems` | `[]` |
| `monsterTemplates.missingRaw` | `0`（模板都能在原始 bestiary 里找到） |
| `classes.multiVersion` | `[]`（2024 覆盖后不该有同名多版） |
| `subclasses.legacyOnly` | `0`（不该有挂在不存在的职业版本下的子职） |
| `subclasses.inherited` | 应为一两百（旧子职借 2014 内容的量） |

抽查几个具体条目（在项目根执行）：

```python
python -c "import json;d=json.load(open('src/MeetingRoom.Host/data/rules/rules-data.json',encoding='utf-8'));
print([x['id'] for x in d['spells'] if x['name']=='Fireball'])          # 只该有 XPHB
print([x['id'] for x in d['optionalFeatures'] if 'EI' in x['featureTypes']][:3])
print([(c['name'],len(c.get('features') or [])) for c in d['classes']])"
```

## 8 已知缺口

| 缺口 | 说明 |
| --- | --- |
| 子职 `cnName` 为空 | 中文包里子职的 `className` 是中文（“法师”），拼 key 对不上英文职业名；目前只有英文名与短名可检索 |
| 21 条召唤物无 HP | 数据本身无固定值（按施法者等级算），不是导出缺陷 |
| `refClassFeature` 未展开 | 牧师/武僧各有 6 条这种引用（指向职业内的可选子特性），目前只记 ID 不带正文 |
| 部分 XGE 老专长没有 `category` | 原始数据就没有该字段，不是丢失 |
| `classTableGroups` 未导出 | 法术位/准备数表；2024 版主要由 `casterProgression`（full/half/pact）驱动，暂不需要 |
