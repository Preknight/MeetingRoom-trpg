# 地图编辑器设计（自带地图数据，替代 OBR 桥）

> 背景：原方案靠 Owlbear Rodeo + 本地桥（HTTPS 自签证书 + 扩展 + CORS + esm.sh CDN）取实时快照，
> 实测连接极不稳定（CORS 缓存、CDN 超时、扩展不上报）。而我们真正需要的只有三件：
> **一张底图、一套网格、若干 token 的位置**。
> 因此改为：MeetingRoom 自带一个地图编辑页，画完即用，不再依赖任何外部系统。

---

## 1. 决策

| 项 | 决定 |
| --- | --- |
| 工具形态 | MeetingRoom 内置页面 `/map-editor`（复用 `board.js` 的标定、网格、测距） |
| 数据深度 | 底图 + 网格 + token + **房间 / 墙 / 门** |
| 模型可见性 | **地图结构进说书人上下文**（房间、相对位置、距离、墙体） |
| 与旧 Vtt | `VttOptions` 保留但默认关闭（`meetingroom.json` 里 `vtt.enabled = false`）；不删代码，将来要接回也有位置。接回时的验收清单在《战斗托管设计》§34.1（已标注为历史项） |

为什么不再做独立程序：标定、网格渲染、坐标换算、测距这一套在 `wwwroot/js/board.js` 已经写好，
独立工具要重写一遍；而在同一个 app 里"画完即用"不需要导出/导入两步。

---

## 2. 数据模型（`maps/<id>.json`）

在 F2 已有的 `{id,name,image,grid}` 基础上扩展。**所有坐标都是图片像素坐标**（与 `board.js` 一致），
不引入第二套坐标系。

```jsonc
{
  "id": "map-ab12cd34ef56",
  "name": "地下储藏室",
  "image": { "file": "map-ab12cd34ef56.webp", "width": 4096, "height": 2784 },
  "grid": { "dpi": 81.5, "offsetX": 16, "offsetY": 64, "type": "square", "feetPerCell": 5 },

  "walls": [
    { "id": "w1", "points": [[100,100],[900,100],[900,700]], "kind": "wall" },
    { "id": "w2", "points": [[520,100],[520,700]], "kind": "door", "open": false }
  ],

  "rooms": [
    { "id": "r1", "name": "储藏室", "polygon": [[100,100],[900,100],[900,700],[100,700]],
      "light": "dim", "note": "堆满旧木箱" }
  ],

  "tokens": [
    { "id": "ella",     "name": "Ella",   "x": 800, "y": 600, "visible": true,  "kind": "character" },
    { "id": "goblin-1", "name": "哥布林", "x": 1200, "y": 900, "visible": true,  "kind": "npc" }
  ],

  "updatedAt": 1761526629123
}
```

字段约定：

- `walls[].kind`：`wall`（阻挡通行与视线）/ `door`（`open` 控制是否阻挡）/ `window`（不挡通行，挡视线可选）；
- `rooms[].polygon`：闭合多边形，首尾不重复；`light` 取 `bright | dim | dark`；
- `tokens[].id` **必须等于角色 id**（与 `SheetStore`、`roleplay.state.cast` 同名），这样战斗、检定、地图三处引用的是同一个人；
- `tokens[].visible=false` 表示 DM 隐藏（玩家视角不画，也不进上下文）。

## 3. 编辑器（`/map-editor`）

### 3.1 工具条

| 工具 | 行为 |
| --- | --- |
| 选择 / 拖动 | 默认；拖 token 改位置，拖空白平移视图 |
| 标定 | 复用 F4 的点两点反算 `dpi/offset`（**保留**，底图不是整数倍时必须调） |
| 画墙 | 折线：点击加点，双击或 Esc 结束；`wall / door / window` 三选一 |
| 画房间 | 多边形：点击加点，点回起点闭合；填名称与光照 |
| 放 token | 左侧列出 `cast` 角色，点一个再在图上点位置；或从列表拖入 |
| 测距 | 两点显示格数与尺数（复用 F3） |
| 保存 | 整体 `PUT` 到 `/api/maps/{id}/document` |

### 3.2 交互细节

- 所有绘制都吸附到**网格交点/格心**（可开关吸附，`1/2` 切换），避免手抖；
- 画墙时的最后一点可点回起点闭合，也可双击结束成折线；
- 选中墙/房间后 `Delete` 删除，`Esc` 取消选中；
- 撤销栈至少支持 20 步（`Ctrl+Z` / `Ctrl+Shift+Z`）；
- 缩放平移与 `board.js` 的视口一致，绘制在图片像素坐标下进行，缩放不影响落点。

## 4. 服务端

### 4.1 端点

已有（F2）：`POST /api/maps/upload`、`GET /api/maps`、`GET /api/maps/{id}/content`、`PUT /api/maps/{id}/calibration`、`DELETE /api/maps/{id}`。

新增：

```
GET  /api/maps/{id}/document      → 完整 MapDocument（含 walls/rooms/tokens）
PUT  /api/maps/{id}/document      → 整体替换（校验后写入，保留 image/grid 不变）
```

`PUT` 的校验：

- `tokens[].id` 必须能在 `cast`（或已知角色 id）里找到，否则**拒绝并点名**——防止拼错导致地图上的 token 永远不跟角色关联；
- `rooms[].polygon` 至少 3 点；
- `walls[].points` 至少 2 点；
- `walls[].kind` / `rooms[].light` 取值必须在枚举内；
- 校验失败**不做部分写入**。

### 4.2 存储

`maps/<id>.json` 直接扩字段；已有文件缺 `walls/rooms/tokens` 时按空数组处理（向后兼容，F2/F4 的旧文件不用迁移）。

## 5. 上下文注入（说书人可见）

地图不是给前端看的装饰，它要变成模型能算的空间。注入放在**角色节**（逐轮刷新，不进前缀，不破缓存），
格式紧凑、只给当前会话需要的部分：

```
【地图】地下储藏室（格宽 81.5px = 5 尺）
房间：储藏室（约 10×7 格，昏暗，堆满旧木箱）
角色：Ella 在储藏室西北角；哥布林-1 在储藏室东侧 3 格；哥布林-2 在走廊（被一扇关闭的门隔开）
```

规则：

- **只给 `visible != false` 的 token**；DM 隐藏的一律不出现；
- 距离按 `dpi × feetPerCell` 换算，输出「格 + 尺」两种单位（模型对"3 格"更敏感）；
- 房间归属靠点在多边形内判定；落在房间外的 token 报「未登记区域」；
- 有墙阻隔时，文案要**说明是隔墙距离**（"直线 6 格，但隔着一堵墙"），不要给出会误导的直线距离；
- 总长度控制在 ~200 字以内（一张图通常 2–6 个房间、3–8 个 token）。超出时按"离当前行动者最近"裁剪。

> 这一段与旧的 `VttContext.AnchorFor` 思路相同，但数据源从桥快照换成本地文档，且多了房间与墙。

---

## 6. 与战斗、测距的联动

- **测距**：战术板两点测距仍用 `dpi × feetPerCell`，与 F3 一致；
- **移动**：拖 token 后立即写回 `document.tokens`（防抖 ~500ms），下一轮的上下文就是新位置；
- **战斗**：`combat_action` 的 `distanceFeet` **仍由说书人显式给**，引擎不猜——但上下文里的距离能让它给对；
- **不做**：不自动把 token 距离写进 `combat_action`（避免"引擎偷偷替模型决定位置"）。

## 8. 风险

1. **手绘几何不精确**：吸附与网格显示是主要防线；提供"按住 Shift 正交"再补一层。
2. **上下文膨胀**：地图段必须裁剪，宁可少给几个远处 token，也不要让每轮多几百字。
3. **坐标双源**：`image.width/height` 与文件真实尺寸可能不一致（上传时已从字节头读，值得再核一次）。
4. **旧数据兼容**：F2/F4 生成的 `<id>.json` 没有 `walls/rooms/tokens`，读取时必须按空处理，不能崩。
5. **与旧 Vtt 并存**：`vtt.enabled` 默认保持 `false`；两条路不要同时往上下文里写地图信息。

## 9. 实施记录（M1，2026-10-27）

### 9.1 数据模型落点

没有新建存储文件：`maps/<id>.json` 仍是 `MapAsset`，只**追加** `walls / rooms / tokens / updatedAt` 四个字段
（都有默认值 `null` / `0`）。旧文件缺字段时由 `asset.Walls ?? []` 兜底——**F2/F4 的文件不用迁移**。

对外统一用 `MapDocument`（`image` / `grid` / `walls` / `rooms` / `tokens`），映射关系：

| 文档字段 | 存储字段 |
| --- | --- |
| `image.file / width / height` | `fileName / width / height` |
| `grid` | `calibration`（缺省回落 `MapCalibration.Default`） |

`Point2` 用自定义转换器读写 `[x, y]` 数组（几百个点时，键名会把文件撑大一倍）。

### 9.2 端点

```
GET  /api/maps/{id}/document   → MapDocument
PUT  /api/maps/{id}/document   → 整体替换 walls/rooms/tokens（底图与标定不受影响）
```

`PUT` 只收三个数组——底图与标定走各自端点，防止"保存 token 时把标定顺手改回默认值"。

**校验（`MapDocumentValidator`，先全部通过再落盘）** 实测六条：

| 输入 | 结果 |
| --- | --- |
| `polygon` 2 点 | 400 `房间 r1 的多边形至少要 3 个点（现在 2 个）。` |
| `points` 1 点 | 400 `墙 w1 至少要 2 个点（现在 1 个）。` |
| `kind: fence` | 400 `墙 w1 的 kind 不合法：fence（只能是 wall / door / window）。` |
| `light: neon` | 400 `房间 r1 的 light 不合法：neon（只能是 bright / dim / dark）。` |
| 重复 token id | 400 `token 的 id 重复：ella` |
| 未知 token id | 400 `这些 token 的 id 不是已知角色：goblin-9。已知角色：client、coroner、detective…` |

六次非法 `PUT` 之后再读文档，仍是上一次合法写入的状态——**没有部分写入**。
已知角色取自 `RoleplaySession.ActorIds`（新加的只读投影，即会话在场角色）；没有会话时为空 → 任何 token 都被拒。

### 9.3 编辑器（`/map-editor`）

`wwwroot/map-editor.html` + `wwwroot/js/map-editor.js`，**独立于 `main.js`**（那里已经因为变量重名崩过一次）。

`board.js` 只加两个入口，默认行为不变：
- `setMapId(id)`：指定看哪张图（原来固定取"第一张已标定的"）；
- `setTokenDragHandler((actorId, phase, point) => …)`：拖 token 回调（`start / move / end`）。
  没有设置回调时，点 token 仍只是广播 `meetingroom:token-click`。

交互：点左侧角色 → 图上点位置（同一角色再点=移动）；拖 token 实时跟随、**松手才写回**；列表里勾选可见性 / 移除；
保存按 500ms 防抖；标定复用 `board.js` 自带按钮（它发 `meetingroom:board-calibrate`，编辑器算 `dpi` 并 `PUT /calibration`）。

### 9.4 验收

- **放 token + 保存 + 刷新**：点「侦探」落在 `1687,1532` → 自动保存 → 刷新后仍是 `1687,1532`（SVG `transform="translate(1687.3… 1531.7…)"`）。
- **拖 token + 防抖 + 刷新**：指针拖到屏幕 +120px → 内存 `2552,1964` → 状态「正在保存…」→ 1.2s 后「已保存」→ 刷新后仍是 `2552,1964`。
- **旧文件兼容**：`map-052ee599d84c.json`（F4 时代，只有 image + calibration）`GET document` 返回
  `walls: [] / rooms: [] / tokens: []`，网格正常（`dpi 81.5 / offset 16,64`）。**这条是在该文件被写入新数据之前实测的。**
- **未知 token 被拒并点名**：见上表。
- 指纹未变（`86fec15f…` / `7c1ee128…`）。

### 9.5 坑

**`let document = null;` 遮蔽了全局 `document`** → 模块级 TDZ，`document.getElementById(...)` 全部抛
`ReferenceError: Cannot access 'document' before initialization`，整页只剩静态 HTML。
与 §31.5（`main.js` 变量重名）是同一类错：**前端模块的语法/引用错不报在 UI 上，只在 console**。
数据变量一律避开 `document / window / location / history / top / name`。

### 9.6 未做 / 已知限制

> **状态更新（2026-10-27 13:48）**：第 1、2 条已由后续批次完成（墙/房间绘制见 §10，标定表单见 §16）；其余仍成立。

- **墙 / 房间绘制**是 M2：本批 schema 与校验已就位，但编辑器不能画 —— **已完成（§10，M2）**；
- 标定用 `window.prompt` 填跨格数，没搬 F4 那套浮层（M1 只需"能标定"）—— **已改（§16，2026-10-27 13:42，页面内表单，不再有原生对话框）**；
- `PUT /document` 的 `tokens` 是**整体替换**——两人同时编辑会互相覆盖（单机使用，暂不处理）；
- 地图区域高度没撑满窗口（截图里下方留白），属于 M2 的排版工作。

## 10. 实施记录（M2：墙与房间，2026-10-27）

**指纹未变**（`86fec15f…` / `7c1ee128…`）——本批只动前端与编辑器。

### 10.1 渲染（`board.js`，叙事战术板也受益）

`buildLayer` 现在返回 `[grid, rooms, walls, tokens, measure, picks]`：

- **房间**：`<polygon class="board-room">` + 居中的名称 `<text class="board-room-label">`；
  `fill-opacity: .1`（设计文档要求 ≤ .12，否则盖掉底图手绘细节）；缩放 < 0.55 时由 CSS 隐掉名字（墙与填充仍在）。
- **墙**：`<polyline class="board-wall board-wall--{kind}">`，深色实线；门是短划虚线、`open=true` 更疏更淡；
  窗是长划 + 点。线宽用 `vector-effect: non-scaling-stroke`，缩放后不变粗。
- 数据来源：叙事页面里 board **按地图 id 自己拉** `GET /api/maps/{id}/document`（`lastDocumentMapId` 去重）；
  编辑器用 `setDocument()` 直接推（它手上就是最新的一份）。

### 10.2 编辑器交互

| 能力 | 实现要点 |
| --- | --- |
| 画墙 | 点击加点，双击或 Esc 结束；`wall / door / window` 下拉切换（默认 `open:false`） |
| 画房间 | 点击加点，**点回起点闭合**；闭合后弹页面内表单填名称与光照（默认 `dim`） |
| 吸附 | 默认吸格点，按钮切换格心；**按住 Alt 临时关闭**；坐标实测对 `dpi` 取模为 0 |
| 正交 | 画墙时按住 Shift，相对上一点锁定水平/垂直 |
| 选中 | 点墙/房间高亮（`--selected`），顶点画成可拖的手柄；`Delete` 删除、`Esc` 取消 |
| 拖顶点 | 拖拽只改那一个索引，松手立即保存 |
| 撤销/重做 | 快照栈 30 步，覆盖绘制、删对象、拖顶点、拖 token；`Ctrl+Z` / `Ctrl+Shift+Z` |

顶点层用 **HTML 绝对定位**（不复制 board 的视图变换），几何按 `object-fit: contain` 的实际贴图框算——
第一次写成了"元素框宽度"，宽高比不一致时会整体错位。

### 10.3 验收

```
吸附：点 (500,400) → [505,390]；(905,400) → [912.5,390]
      (505-16)/81.5 = 6.0、(390-64)/81.5 = 4.0  → 误差 0
画墙 → 3 点 → 双击结束 → walls: [{kind:"wall", points:[[505,390],[912.5,390],[912.5,797.5]]}]
画门 / 画窗 → kinds: ["wall","door","window","window"]
画房间 → 表单（名称「储藏室」、光照 dark）→ polygon 4 点
拖顶点 → 只有 index 0 变：[505,390] → [749.5,471.5]
Ctrl+Z ×3 → walls 7 → 6 → 5 → 4
刷新 → docWalls [wall,door,window,window] ↔ svg [--wall,--door,--window,--window]；房间 fillOpacity = 0.1
叙事战术板 → #tactical-board 里出现同一个 room「储藏室」+ 四段墙
```

### 10.4 踩的坑（都值得记）

1. **`refreshBoard` 没把文档推给 board**：M1 阶段那次修改因 heredoc 失败没落盘，而 M2 只插入了新块，
   于是"编辑器的改动永远到不了渲染层"——表现为**数据对、界面不变**。最后用 `board.setDocument()` 显式推送修好。
2. **`requestAnimationFrame` 在不可见窗口不触发**：`scheduleRender` 用 rAF 时，受控浏览器/后台标签页里
   回调根本不跑，同样表现为"改了没重绘"。改成 `setTimeout(…, 16)`。
3. **`setDocument` 顺手作废图层缓存**（`lastGridState = ''`）：否则 key 没变就不重建。
4. `window.prompt` 在受控浏览器里不可用，也没法一次填两个字段——改成页面内表单（也更像"小表单"）。

### 10.5 未做

- 墙/房间的**右键菜单**（改名称/光照/开合门）——M2 只做了删除；门开合目前只能改 JSON；
- 撤销栈不跨刷新（内存态）；
- 战术板里的房间/墙不可交互（只显示，符合设计）。

## 11. 实施记录（M3：地图结构进说书人上下文，2026-10-27）

**指纹未变**（`86fec15f…` / `7c1ee128…`）——没有加工具、没改提示词。

### 11.1 生成器（`Core/Maps/MapContextBuilder`）

`Build(document, focusActorId)` → 一段文字，**空串表示"这一段不出"**（没有可见 token 或未标定）。

```
【地图】011-1.01-neverdeath-player（格宽 81.5px = 5 尺）
房间：储藏室（约 12×10 格，昏暗，堆满旧木箱）；走廊（约 10×10 格，黑暗）
角色：Ella 在储藏室；侦探 在储藏室正东，5 格 / 25 尺；法医 在走廊正东（直线 15 格 / 75 尺，但隔着一堵墙）
```

规则实现（逐条对应设计文档 §5）：

| 规则 | 实现 |
| --- | --- |
| 只给 `visible != false` | `Tokens.Where(t => t.Visible)`；隐藏的连"另有 N 个"都不进 |
| 距离给格 + 尺 | `Math.Round(像素距离 / dpi)` 格，尺 = 格 × `feetPerCell`（两者互相对得上） |
| 房间归属 | 射线法 `InsidePolygon`；落在所有房间外写"未登记区域" |
| 隔墙必须说 | 两点连线与 `kind=wall` 或 `open=false` 的门相交 → "（直线 N 格 / M 尺，但隔着一堵墙／一扇关着的门）"；**开着的门与窗不算隔** |
| ≤ 200 字 | 角色行预算 = 200 − 标题 − 房间行 − 换行；超了按"离焦点由近到远"保留，其余收成"另有 N 个目标在别处" |
| 焦点 | 战斗中有当前行动者就用它；**没有战斗时退化为第一个可见 token**（否则没有任何距离可给） |

### 11.2 接线

`RoleplayOptions.MapDocumentProvider`（`Func<MapDocument?>`）由 `WorkspaceSessionFactory` 注入：
工作空间 `maps/` 下**第一张已标定的**地图（与编辑器、战术板同一口径）。
`RoleplaySession.MapSectionFor` 的分支顺序：**旧 Vtt 通道（`vtt.enabled=true`）优先，两者互斥**（§8.5）；
否则本地地图只给**说书人**（它是唯一需要算距离的角色），其他角色不注入。

## 14. 实施记录（r4 高危项：token 不接指针事件，2026-10-27）

**指纹未变**（工具面 `86fec15f…`、前缀 `c5951d9d…`）——只动 CSS 与前端。

### 14.1 根因

`.board-overlay { pointer-events: none }` 是**继承属性**，而 `.board-token` 从未重置回来。
交互全部挂在 `wrap` 上、靠 `event.target.closest('.board-token')` 判定，于是：

```
elementFromPoint(token 圆心) → IMG.board-map     // 修复前
closest('.board-token') → null → 拖 token / 点击高亮 / 双击 Sheet 三条链路全失效
```

此前 F3/F4 的验收都用 `dispatchEvent` 直接打在 token 元素上，**事件是伪造的，永远命中**——所以从没暴露。

### 14.2 修法

```css
.board-token { pointer-events: auto; cursor: grab; }      /* 继承来的 none 必须显式重置 */
.board-token:active { cursor: grabbing; }
.board-token-ring, .board-token-badge, .board-token-label { pointer-events: none; }  /* 装饰不抢点击 */
```

**徽标与环的外接矩形分离**：原来徽标在 `(0.95r, -0.95r)`，外接矩形与环相交约 3px。
改为按**轴向投影**反推距离（45° 时轴向分量 = d·cos45）：

```
ringRadius  = 1.45r + 1.5（环描边的 non-scaling 宽度换算成图片像素）
axialNeeded = ringRadius + max(徽标半宽, 徽标半高) + 2 屏幕 px
distance    = axialNeeded / cos(45°)
```

实测（`elementFromPoint` 与 `getBoundingClientRect`）：**100% 与 125% DPR 下 gap 都是 4px（X）/ 5px（Y），不重叠**。

### 14.3 真实鼠标链路验收（CDP `Input.dispatchMouseEvent`）

所有操作都发到 `document.elementFromPoint(cx, cy)` 命中的**最上层元素**（或直接 CDP 鼠标事件），
不再对 token 元素 `dispatchEvent`。

2. 就算接上，**`.editor-overlay` 被 `.board` 盖住**（两者都在 `#editor-board` 里，overlay 在 DOM 里先出现，

### 18.2 两个既有缺口（不是本批引入）

**① 前端用"是否在跑"当模式判据**（`wwwroot/js/store.js`）：

```js
const active = roleplay.status !== 'idle';   // ← 重启后旧会话是 idle，于是退回会议模式
```

重启后没有运行态恢复，旧会话的 `status` 就是 `idle`——但它是**一场叙事**，不是会议。

修：模式看"这场是什么"，不看"它跑不跑"：

```js
const active = Boolean(payload.storyId) || roleplay.status !== 'idle';
```

**进叙事模式 ≠ 假装进行中**：状态文本仍照实显示（`idle` → 「未开始」、`paused` → 「已暂停」、`running` → 「进行中」）。
与会者列随之显示该会话的 `cast`（即使 idle）。

**② `resume` 假成功**（`SessionCore.ResumeAsync` + 端点）：

```csharp
public Task ResumeAsync(...) {
    if (_status != MeetingStatus.Paused) return Task.CompletedTask;   // ← 什么都没做
    ...
}
// 端点却无条件：return Results.Ok(new { status = "running" });      // ← 假成功
```

修：端点先读快照里的 `status`（`RoleplayStatusProbe.StatusOf(session.Snapshot())`），按状态分派：

| 当前状态 | 行为 |
| --- | --- |
| `running` | 200（幂等） |
| `paused` | 调 `ResumeAsync` → **再读一次状态**，真的是 `running` 才 200，否则 409 |
| `idle` / `ended` / 其它 | **409**：`该会话未处于可恢复状态（当前 idle）。它没有在跑，用「打开」重新进入这一场，而不是 resume。` |

**语义定调**：`resume` 只负责"把暂停的继续跑"；"把没在跑的会话拉起来"是 `open` 的事，两者不混。
