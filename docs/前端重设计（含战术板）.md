# 前端重设计（含战术板）

> 目标：全屏跑团界面。战斗时把「剧情」与「战术板（地图 + token + 距离）」并列，
> 其余列按需折叠；非战斗时回到现有六列布局。
> 地图采用**静态底图 + 叠加层**（方式 2），不嵌入 OBR 页面。

---

## 1. 目标与约束

**目标**

- 全屏（1920×1080 / 2560×1440）下，剧情与战术板同时可见，不互相挤压。
- 地图上的 token 位置、距离、可见性与后端一致；**玩家视角不泄露未揭示目标**。
- 底图可由 DM 导入并标定，标定结果可复用（同一张图下次直接用）。

**约束**

- 后端判定逻辑不动；只增加投影字段与地图资源端点。
- 地图是**只读展示**：拖 token 仍由 DM 在 OBR 里做，前端不改地图状态。
- 底图来源（已核实）：
  - **OBR 截图**（主路径）：DM 在房间里截图 → 上传；
  - **自备模组图**（次路径）：从购买的模组包导出；
  - ⚠️ **5e tools 镜像里没有 `img` 目录**（v2.39.0 只有 `data/bestiary/items/spells` 等页面目录，图片走 `cdn.5e.tools` 外链），所以“从 5etools 取官方模组地图”这条路不成立。

---

## 2. 现状（已核实）

- 六列，宽度 `240 / 240 / flex / 260 / 200 / 200`；固定列合计 1140。
- `panel-layout.js` 已实现：拖分隔条改宽、顶栏开关折叠、状态存 `localStorage`。
- 可折叠分组：`sidebar` / `archived` / `main` / `review` / `rail`（**rail 是整体**，不能单独折后台列）。
- 已存在图片上传通道：`/api/images/upload`（字节上传）、`content / list / delete`，配 `ImageAssetStore`。

---

## 3. 布局

### 3.1 两种模式

| 模式 | 列状态 | `main` |
| --- | --- | --- |
| **默认**（非战斗） | 六列原样 | 剧情 + 指令区 |
| **战斗** | 折叠 `sidebar` / `review` / `rail-r`；保留 `archived`（查设定）与 `rail-l`（先攻序/HP） | 左右分栏 **55 / 45**：剧情 ｜ 战术板 |

1920 屏下：战斗模式固定列 240（archived）+ 200（rail-l）= 440，`main` ≈ 1480，战术板约 **660px**。
2560 屏下：战术板约 **940px**。够放一张 30×20 格的地图并看清 token。

### 3.2 切换方式

- 顶部「战斗条」：轮次、当前行动者、`结束战斗`；
- 进入战斗（`combat-start` 事件）自动切「战斗」模式，结束（`combat-end`）自动恢复；
- 手动开关保留（顶栏按钮），状态存 `localStorage`，键名加 `preset: "combat" | "default"`；
- **退出战斗不丢用户自定义宽度**：预设只改 `hidden` 集合，不改用户拖过的宽度。

### 3.3 需要的小改动

- 把 `rail-l` / `rail-r` 从 `COLUMNS` 提升到 `GROUPS`，使「后台记录」可单独折叠（否则只能整块折掉与会者）；
- 新增 `main` 内部分栏：`main` 变成 `grid-template-columns: 55% 45%`（分栏比例可拖，存 localStorage）。

## 4. 战术板

### 4.1 组成

```
<div class="board">
  <img class="board-map">              ← 底图（object-fit: contain）
  <svg class="board-overlay">           ← 网格 / token / 标尺 / 标签
  <div class="board-toolbar">           ← 缩放、适应窗口、网格显隐、视角切换
</div>
```

用 **单张 `<img>` + SVG 叠加**，不用 canvas 每帧重绘：缩放平移只改 CSS `transform`，大图也稳。

### 4.2 坐标换算

- 底图像素 → 显示像素：`display = (px * scale) + offset`；
- 网格参数来自桥（`grid.dpi / measurement / scale`）或标定结果；
- token 坐标来自桥的像素坐标，按同一套 `scale/offset` 换算；
- 距离直接用桥算好的 `measurement`（标尺读数）或按 `dpi × scale` 换算，**前端不自己发明算法**。

### 4.3 底图导入与标定

1. 上传图片（复用 `/api/images/upload` 或新建 `/api/maps/upload`）；
2. 标定：在地图上拖两条参考线（横向对齐网格线、纵向对齐网格线），输入「这条线跨了几格」→ 反算 `dpi`；再拖一次确定 `offsetX/offsetY`；
3. 保存为 `maps/<id>.json`：`{ dpi, offsetX, offsetY, gridType, scale, sourceNote }`；
4. 下次同一张图直接复用标定；可手动微调 `dpi/offset`（±1 按钮）。

### 4.4 可见性

- **DM 视角**：所有 token 都画（未登记的用虚线描边）；
- **玩家视角**：只画 `visible == true` 的 token；未登记目标完全不出现在图上；
- 视角切换是**显示层**的开关，**真正的上下文过滤在后端**（`VttContext` 已按 `visible` 过滤）。前端切到“玩家视角”只是模拟玩家看到什么，不能替代后端过滤。

### 4.5 交互

| 操作 | 行为 |
| --- | --- |
| 滚轮 | 以鼠标位置为中心缩放（0.5×–3×） |
| 拖拽空白 | 平移 |
| 点 token | 高亮对应「与会者」行，并显示名字/HP/状态浮标 |
| 点与会者行 | 反向高亮地图上的 token |
| 点两点 | 临时测距（显示格数与尺数），Esc 清除 |
| 双击 token | 打开该角色的 Sheet 摘要（只读：HP/AC/状态/法术位） |
| 视角切换 | DM / 玩家 |

## 5. 数据契约

### 5.1 地图资源（新增）

```
POST   /api/maps/upload            → { id, width, height }
GET    /api/maps                   → [{ id, name, width, height, calibrated }]
GET    /api/maps/{id}/content      → image/png
PUT    /api/maps/{id}/calibration  → { dpi, offsetX, offsetY, gridType, scale }
DELETE /api/maps/{id}
```

- 存储：工作空间 `maps/<id>.png` + `<id>.json`（与现有 `ImageAssetStore` 同模式，但独立目录，避免和生成图片混在一起）；
- 上传大小上限与 `images.maxOutputBytes` 同量级（16 MB），超过先在前端缩到长边 4096。

### 5.2 战斗投影（新增）

`roleplay.state` 增加 `combat` 节点：

```jsonc
"combat": {
  "encounterId": "enc-1", "round": 3, "phase": "active",
  "order": [{"actor":"ella","initiative":18},{"actor":"goblin-1","initiative":12}],
  "currentActor": "ella",
  "budget": {"action":true,"bonus":true,"reaction":false,"movementFeet":15},
  "combatants": [{"id":"ella","name":"Ella","cnName":"艾拉","hp":12,"maxHp":30,
                  "status":"alive","conditions":["prone"]}]
}
```

- 没有战斗时 `combat: null`；
- `hp/status` 来自 `SheetStore`，**不缓存到前端**；
- 事件 `roleplay.combat` 已存在，前端只需按事件刷新。

### 5.3 地图快照（沿用）

`roleplay.state.vtt` 已有：`grid / tokens / selected / rulers`，战术板直接消费。

## 6. 服务端改动（最小）

1. 新增 `/api/maps/*` 六个端点（复用 `ImageAssetStore` 的路径防护与字节校验）；

3. 前端静态文件：`wwwroot/js/board.js`（战术板）、`panel-layout.js` 拆分 rail、`main` 分栏。

## 8. 风险

1. **底图版权**：模组地图仅本地自用，地图文件放工作空间、不进仓库。
2. **标定误差**：不同底图 dpi 不同（150/100/70 常见），提供 ±1 微调与“对齐线”可视化，不靠肉眼硬猜。
3. **大图性能**：单 img + SVG，缩放只改 transform；超过 4096 长边先缩图，避免 8K 原图卡顿。
4. **可见性误用**：前端“玩家视角”只是模拟，**不能**替代后端 `visible` 过滤；任何把前端开关当作安全边界的做法都要拒绝。
5. **5e tools 无地图**：已核实镜像无 `img` 目录，底图主路径只能是 OBR 截图或自备模组图，设计里不要预留“从 5etools 拉图”的分支。
