# 角色卡与数值表模板

> 2026-11-03 19:50 初版。依据 `RoleCard` / `Sheet` / `SheetValidator` / `RoleSheetLoader` 的实际实现写。
> 本文只讲**当前已经建模的字段**；D&D 5e 标准角色表里有、但 MeetingRoom 还没建模的部分单列在 §6。

---

## 1 两张文件

一个角色 = `data/roles/<id>.md` + `data/roles/<id>.sheet.json`。

- `.md` 是**身份与行为**（跨会话复用）
- `.sheet.json` 是**数值**（战斗与判定用）
- 文件名前缀必须一致（`bran.md` ↔ `bran.sheet.json`），且 `id` 字段要相同
- **没有 `.sheet.json` 也能用**：角色照常发言，只是战斗/检定时会提示"该角色没有数值表"

---

## 2 `<id>.md`：front-matter 与正文

```markdown
---
id: bran                       # 必填，小写英文+连字符，与文件名一致
name: Bran                     # 必填，显示名
title: 矮人战士                 # 可选，卡片上的一行简述
summary: 脾气不好的老兵…        # 可选，一句话摘要（渐进式披露用）
role: member                   # member（默认）| host（主持人）
model: ""                      # 可选，留空用全局默认
effort: ""                     # 可选，注意：当前版本未消费此字段
allowedTools: []               # 可选，工具白名单（见 §7 注意）
vttTokenId: tok-bran           # 可选，旧 OBR 桥的 token 映射，现在基本不用
readOnly: false                # 可选
---

正文写：背景、职责、行为准则、发言风格。

- 只写你自己的动作、判断与台词，不要替别人说话或做决定。
- 不要写元话语，不要提「地图」「坐标」「距离」这类词。
```

**正文是唯一进该角色会话的设定文本**，不进共享前缀——所以可以写细，不会影响别人。

## 3 `<id>.sheet.json`：字段全表

### 3.1 必填（缺任何一个，整张表被拒绝）

```jsonc
{
  "characterId": "bran",        // 必填，与文件名/卡 id 一致
  "maxHp": 44,                  // 必填，> 0
  "currentHp": 44,              // 必填，0..maxHp
  "tempHp": 0,                  // 必填，>= 0（0 是合法值）
  "armorClass": 17,             // 必填，> 0
  "proficiencyBonus": 2,        // 必填，1..10
  "abilities": {                // 必填，六项一个都不能少，每项 1..30
    "str": 17, "dex": 12, "con": 16,
    "int": 9,  "wis": 11, "cha": 10
  }
}
```

**六属性必须齐全**——缺哪项报「未填：abilities.strength」这种，不会拿 10 顶上。

### 3.2 可选（不填 = 没有该条目，不算错）

```jsonc
{
  "saveProficiencies": ["strength", "constitution"],   // 豁免熟练，用属性全名
  "skills": {                                          // 技能 → 加值（含熟练加值的最终值）
    "athletics": 5,
    "intimidation": 2
  },
  "spellSlots": {                                      // 环级(1..9) → {max, used}
    "1": { "max": 4, "used": 0 },
    "2": { "max": 3, "used": 1 }
  },
  "attacks": [ /* 见 §4 */ ],
  "conditions": [],                                    // 当前状态，如 ["prone", "poisoned"]
  "concentration": null,                               // 运行时字段，一般留空
  "deathSaves": null,                                  // 运行时字段，一般留空
  "status": "alive"                                    // alive | dying | stable | dead
}
```

`concentration` / `deathSaves` / `status` 是**战斗过程中会被引擎改写的运行时字段**，手写卡一般不用填，留 `null` / 默认即可。

## 4 `attacks`：武器攻击

```jsonc
"attacks": [
  {
    "weaponId": "Longsword|XPHB",   // 必填，必须是规则包里存在的物品 id（name|source）
    "attackBonus": 5,               // 与 saveDC 至少给一个
    "damageDice": "1d8+3",          // NdM±P；留空表示这件武器不掷伤害（纯控制）
    "damageType": "slashing",       // 英文类型：slashing / piercing / fire …
    "masteries": ["Sap"]            // 可选，2024 版武器精通
  },
  {
    "weaponId": "Sacred Flame|XPHB",
    "saveDC": 13,                   // 有些效果是让目标豁免，不是打 AC
    "damageDice": "1d8",
    "damageType": "radiant"
  }
]
```

**`attackBonus` 与 `saveDC` 至少给一个**——两者都没有就是"这次攻击没法结算"。

**`weaponId` 必须是规则包里真实存在的条目**（格式 `名称|书名`）。当前规则包是 2024 版，所以用 `|XPHB` 而不是 `|PHB`。写完可以用工具核对：

```
lookup_rule { "query": "Longsword", "kind": "item" }
```

## 5 简写与规范名

两者都接受，**规范名优先**：

| 简写 | 规范名 |
|---|---|
| `ac` | `armorClass` |
| `profBonus` | `proficiencyBonus` |
| `str` / `dex` / `con` / `int` / `wis` / `cha` | `strength` / `dexterity` / `constitution` / `intelligence` / `wisdom` / `charisma` |

**同现且值不同 → 整张表被拒绝**（不静默取其一）；值相同则自动去重。

⚠️ **`level` 字段不存在**。写了 `level` 会被拒绝并提示：
> Sheet 没有 level 字段（戏法档位请在施法时用 combat_action 的 characterLevel 给）

## 6 目前**不支持**的 D&D 标准字段

这些写进 `.sheet.json` 会被当成未知字段（`UnmappedMemberHandling.Disallow`，直接报错），**应当写进 `.md` 正文**：

| 字段 | 现状 |
|---|---|
| 职业与等级 | 未建模（`level` 会被拒） |
| 速度 / 体型 / 感官 / 语言 | 未建模 |
| 抗性 / 免疫 / 易伤 | 未建模 |
| 经验值 / 阵营 / 背景 | 未建模 |
| 装备清单（护甲、物品、钱） | 未建模；只有 `attacks` 里的武器 id |
| 专长 / 特性 | 未建模（写在正文里） |
| 法术清单（已知/准备） | 未建模；只有法术位数量 |

如果你需要这些参与**机制结算**（比如抗性减伤），得先扩展 `Sheet` 模型。

```markdown

name: Bran
title: 矮人战士
summary: 脾气不好的老兵，能用斧子解决的事绝不多说一句
role: member
---

你是 Bran：一个打了二十年仗的矮人战士，胡子编成两股，斧子比人还沉。

- 你说话短，一句到两句就够，常用「走」「让开」「我先上」这类词。不解释理由。
- 你只写你自己看到的、做的、说的。不要替别人说话，也不要替别人做决定。
- 你看不惯磨蹭和推让；队伍里有人犹豫时，你会直接往前走 —— 但不会丢下同伴不管。
- 你识字不多，不信书本和预兆，只信手感和经验。
- 不要写元话语，不要提「地图」「坐标」「距离计算」这类词；远近写成自然描述即可。
```

## 8 写完怎么验

1. **语法**：JSON 必须合法（多余逗号、中文引号都会整张表作废）。
2. **必填**：五项 vitals + 六属性。
3. **`weaponId` 存在**：用 `lookup_rule { "query": "武器名", "kind": "item" }` 核对。
4. **启动后看日志**：`RoleSheetLoader` 会把问题一次性打出来，格式是
   `bran.sheet.json 校验不过：xxx；yyy——该角色按「没有数值表」处理。`
5. 一次只改一处、改完重启，比一次性写满再排错快。

## 9 常见错误速查

| 现象 | 原因 |
|---|---|
| 「未填：abilities.wisdom」 | 六属性缺项 |
| 「Sheet 没有 level 字段」 | 写了 `level` |
| 「ac 与 armorClass 冲突」 | 两个都写且值不同 |
| 「该角色按『没有数值表』处理」 | 任一必填缺失或 JSON 非法 |
| 战斗时「查不到武器」 | `weaponId` 不在规则包里，或写成了 `|PHB`（当前包是 2024） |
| 「这次攻击没法结算」 | `attacks[i]` 既没 `attackBonus` 也没 `saveDC` |
| 法术位报错 | 环级不在 1..9，或 `used > max` |
